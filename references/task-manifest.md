# 任务清单与时间轴

首次使用先按 SKILL.md 的两轮初始化流程确认 ComfyUI 位置、工作流和默认生成参数。每次任务再确认参考视频是否保留原音频，使用 `prepare.py init --profile <配置文件> --reference-audio keep` 或 `drop` 建档。`settings.keep_reference_audio` 控制工作副本、原始分段和补齐参考视频是否保留音轨，补齐尾段为静音。源片没有音轨时告知用户。Agent 通过拉片填写 `requirements`、`characters` 和 `segments`。下面省略初始化已填写的字段：

```json
{
  "requirements": "参考图A替换长发人物；戴帽人物保留原样。动作、场景和原片风格保留。",
  "characters": {
    "long-hair": {
      "source_identity": "源片长发人物；首镜位于画面左侧，后续用面部与发型追踪",
      "reference_image": "参考图/A.png",
      "target_identity": "实际查看参考图后写入脸、头发、体型、衣服与可见配饰"
    },
    "hat": {
      "source_identity": "源片戴帽人物",
      "reference_image": null
    }
  },
  "segments": [
    {
      "id": "001",
      "start_frame": 0,
      "end_frame": 48,
      "cast": ["long-hair", "hat"],
      "synopsis": "两人同框，长发人物伸手递出道具，戴帽人物接过。",
      "cut_reason": "源片真实硬切",
      "end_state": "道具已在戴帽人物手中，两人仍保持原左右位置"
    }
  ]
}
```

例子只展示字段含义；实际段数、结束帧、人物和动作必须来自本次视频。每个 `segment` 只覆盖一个连续镜头或同一长镜头的一部分；所有真实切镜都必须落在段边界，不能让一个生成段跨越多个镜头。`segments` 依次覆盖全部工作源片，从 0 到 `source_frame_count`；`end_frame` 不包含在本段内。不能照抄这个只有 48 帧的示例到更长视频。

## 人物和参考素材编号

- `characters` 的 key 是全片人物追踪 ID，提示词正文不用这个 ID 或图片文件名。
- 每段 `cast` 按 Agent 确认的稳定顺序列出本段所有可见人物，包括仅露手臂、背面、远景及需要保留的原人物。已经离开画面且整段不出现的人不放进来。
- `cast` 第 N 项对应 `<Subject N>`。有 `reference_image` 的人物才分配 `<Picture N>`，图片编号在本段独立从 1 连续递增。
- 例如 `cast = [保留人物, 替换人物]`：保留人物为 Subject 1，无 Picture；替换人物为 Subject 2，身份来自 Picture 1。不能把 Picture 编号等同全局人物 ID。
- 每段一个 `<Video 1>`，就是本段补齐后的源视频；图片的编号与视频编号独立。
- 某段没有任何待替换人物时，不编写伪换人提示词；脚本保留其原始视觉片段。中文分析中标记为“原样保留”。

`reference_image` 可使用任务目录内的相对路径或绝对路径。通常复制用户提供的图片到 `参考图/`，使用相对路径让任务包更容易检查。人物参考图只锁身份和服装；其白底、多视图排版和站姿不作为画面内容。

## 中文拉片表

在 `拉片分析.md` 中记录：源片与工作源片信息、用户替换要求及角色对照、全片切镜表、光线变化、情绪变化、各段动作、边界前后证据、全局时间与段内时间关系、承接状态及尚待确认项。

时间以实际工作源片帧边界为准：工作源片时间 = 帧号 / 24；段内时间 = 工作源片时间 - 本段开始时间。非 24fps 或 VFR 视频会规范为 24fps 工作副本，原片的帧号不能直接照抄到工作片；以播放时间关联两者，并在分析中注明帧采样转换及不足一帧的时长量化差异。正式提示词中的时间只写原始动作区间，不给补齐末帧编造动作。生成图使用补齐帧数 / 24 作为 seconds，生成结果从头保留本段未补齐的工作片帧数。

`补齐生成用/NNN.txt` 是清单中 synopsis 的副本。真正输入 H3 的是 `提示词/NNN.txt` 的六段全文，脚本不扩写简介。
