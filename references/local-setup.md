# 首次本地设置与工作流绑定

这是两轮对话：先取得使用者提供的 ComfyUI 路径和工作流，读取该文件后再问默认参数。不能先套入某套预设再让使用者修改。

## 检查和确认

在 Skill 根目录执行，尖括号内容替换为使用者给出的真实位置：

```powershell
python scripts/setup.py inspect --comfyui "<ComfyUI 根目录>" --workflow "<使用者提供的工作流.json>" --out .local/inspection.json
```

`profile.parameters` 提供从实际工作流识别出的控件和当前值，不是已激活配置；`adjustable_controls` 列出其余可供确认的控制项。先把对应表展示给使用者，再按答复修改 `profile`。也要确认 `comfy_url`（本机运行服务的 HTTP 地址）、`input_directory` 和 `reference_short_edge`（偶数像素或 `null` 不缩放）。

普通整数、浮点、布尔和名称明确的控件会出现在检查表中。非标准标题、自定义 Sigma 等没有唯一归属时，Agent 对照工作流连线，确认控制的是哪一采，然后询问使用者；不要根据节点数字猜测。不支持的节点家族先说明具体差异，适配确认后再生成；当前脚本面向含单个 `gosick_233_MiniMaxH3EasyV114` 的 UI 工作流，不声称通用支持任意 ComfyUI 模型或 API 格式导出。

用户确认后：

```powershell
python scripts/setup.py save --from .local/inspection.json
```

本地 `.local/config.json` 保存确认后的默认值；初次不存在时 `prepare.py init` 会要求先初始化。重新设置时重复上述两轮流程。不要提交 `.local/`、真实工作流、模型路径或任务素材。

## 绑定格式

每个参数的 `value` 是使用者确认的默认值，`targets` 指向该用户工作流里真实的节点与字段。参数名称可增加，用于绑定自定义采样控制。以下只展示结构，不是可直接套用的配置：

```json
{
  "参数名称": {
    "value": "使用者确认的值",
    "targets": [
      {"node_id": "该工作流里的节点 ID", "widget": "该控件的实际字段名"}
    ]
  }
}
```

`first_resolution` 对应 Easy 节点的 resolution。自定义分辨率同时确认 `width`、`height`。普通档位按源视频画幅计算；非标准画幅以该档位像素预算计算 custom 尺寸。`first_steps`、`second_steps`、`upscale` 等只是识别明确标题时的建议绑定；不会要求节点 ID 与某个作者的工作流相同。

任意绑定既可以指向 Primitive 的 value，也可以直接指向调度器的 steps 或自定义数列控件。链接输入应绑定其上游实际数值来源，不能仅修改接收节点上已被链接覆盖的显示值。若控制器没有保存为工作流中的字段，不能编造绑定。

高动态减少模糊的前端开关若保存了 `first_refiner_id`／`second_refiner_id`，生成副本会同步对应 Sigma Refiner 的执行／旁路状态。步数和 Sigma 数列分别按使用者确认的控件修改，不额外改变采样器或 LoRA。

## 准备和运行边界

`local_h3.py build` 读取本机 `/object_info`，按实时节点定义校验 API 图并复制本次素材到已确认的 input 目录，不提交 GPU 作业。`run` 才按串行队列执行；使用本机接口，不需要生成服务 API key。

UI 工作流按实际连线转换为 API 图，支持旁路和动态组合字段。模型、LoRA、注意力、分块、种子和未要求修改的参数保留在使用者的工作流中。生成图只更换本次提示词、参考素材、时长、画幅和输出前缀，以及已确认的默认参数。原始工作流只读。

二采开关决定采用一采还是二采保存节点，保留原生成后卸载节点。任务放在独立 input 子目录中。完成后保存原生成视频，再裁去补齐帧；当前 `完成分段/` 是视觉片段，最终成片的配音／源音轨复用由使用者另行决定。

## 故障续接

运行报错会记录并退出，由 Agent 依据 SKILL.md 执行最多两次排查修复后的恢复。连接或下载失败且原任务已成功时，直接再次运行批量脚本会复用记录中的 prompt_id；已完成段跳过。

生成本身已在后端失败时，先确认具体原因，保留旧错误，修复本次任务后仅移除该失败段的旧任务条目，再恢复。提交请求响应丢失时先查本次输出前缀及队列／历史，不能直接重复提交。源素材／图改变导致摘要不同，也应只处理受影响段的记录并记录原因。不要清空整个任务或其他任务队列。
